# Conventions

Extracted from the codebase. Follow these; reuse existing patterns over inventing new ones.

## Language & modules

- **TypeScript strict** + `noUncheckedIndexedAccess` — array/record access is `T | undefined`; handle it. Tuple and finite-key `Record<LiteralUnion, T>`/`as const` access stays `T`.
- **ESM + NodeNext** — all relative imports use `.js` extensions in `.ts` source (`import { x } from './config.js'`). Required by `moduleResolution: NodeNext`.
- **No third-party runtime deps** in core/data path — use Node built-ins (`fetch`, `crypto`, `node:util`). `@modelcontextprotocol/sdk` only in `bitget-mcp`.

## Folder structure rules

- Monorepo: `packages/<name>/src`, built to `dist/` via `tsup`. Consumers import core's `dist/`, not src.
- `bitget-core/src/api/<module>.ts` — endpoint-path constants only (`<MODULE>_ENDPOINTS`). Add the constant here first, then reference from the handler. Never hardcode `/api/v2/...` in handlers.
- `bitget-core/src/tools/<module>.ts` — one `register<Module>Tools(): ToolSpec[]` per module.
- Mock routes mirror tool endpoints in `bitget-test-utils/src/server/routes/<module>.ts`.

## Naming

- Files: **lowercase-hyphen** (`copy-trading.ts`, `rate-limiter.ts`).
- Tools: `{module}_{action}_{object}` (`spot_get_ticker`, `futures_place_order`); `account` module omits a redundant prefix where it reads better.
- Endpoint constants: `<MODULE>_ENDPOINTS`, grouped by sub-resource (`SPOT_ENDPOINTS.trade.placeOrder`).
- Register fns: `register<Module>Tools`.

## Adding a tool (the one pattern)

1. Add endpoint constant in `api/<module>.ts`.
2. Add a `ToolSpec` to the module's `register*Tools()` array — set `module`, `isWrite`, `inputSchema`, `description`.
3. Add a matching mock route in `bitget-test-utils` if it hits a new endpoint.
4. Build core, run tests. It flows into MCP, CLI, capabilities, and skill refs automatically — no consumer edits.

## Tool description standard

Each `description` states: one-line function; auth (Public/Private); rate limit (`Rate limit: N req/s per UID|IP`); and `[CAUTION] ...` for writes. Set `isWrite: true` for any mutation so `--read-only` and `destructiveHint` work.

## Parameter / validation patterns

- Validate args via `tools/helpers.ts`: `requireString`, `readString`, `readNumber`, `readBoolean`, `readStringArray`, `readObjectArray`, `assertEnum`, `ensureOneOf`, `compactObject`, `asRecord`.
- String-encoded JSON for array/object params is accepted so CLI and MCP paths behave identically.
- Money/price/size as **string** (avoid float precision). Constrain choices with `enum`. Keep params few and well-described.
- `compactObject({...})` drops undefined/null before sending.

## Error handling patterns

- Throw typed errors from `utils/errors.ts` (`ValidationError`, `ConfigError`, `BitgetApiError`, …). Don't return ad-hoc error strings.
- REST client throws on Bitget `code !== "00000"`; auth codes `40017/40018/40036` → `AuthenticationError`.
- Handlers return `normalize(response)` → `{ endpoint, requestTime, data }`. MCP wraps to `{ tool, ok, data|error, capabilities, timestamp }`.

## Security practices

- Credentials from env only; partial credentials throw. Never log/persist secrets.
- All private requests signed via `signature.ts`; never bypass.
- Respect `isWrite` — it is the read-only gate.

## Testing conventions

- vitest against `bitget-test-utils` `MockServer`; set `BITGET_API_BASE_URL` to it. Mock asserts exact endpoint routes.
- Stateful round-trips live in `state.ts`. Single file: `pnpm vitest run tests/tools/spot-trade.test.ts`; by name: `pnpm vitest run -t "round-trip"`.
- **Build core before consumer tests / smoke test / gen-references.**

## Code style (`.agent/code-style/`)

Authoritative style guide: `.agent/code-style/COMMON.md` (+ `BACK-END-STYLE.md`, `FRONT-END-STYLE.md`). Key rules:
- Single quotes (keep double only when the string contains an apostrophe); no trailing commas; semicolons on every statement, import, export, TS member.
- Object/interface/type members and array items each on their own line.
- Import specifiers on a single line (never wrapped).
- No destructuring assignment — use property/index access (`const a = obj.a;`).
- Never break function-call arguments across lines (object/array-literal args may span).
- Chained calls: first `.method()` on the base line; 2nd dot onward each wraps. `if` always braces.

Note: tiny inline schema literals (`{ type: 'string', description: '...' }`) and short enum arrays are kept inline by existing convention.

## Generated artifacts — do not hand-edit

`bitget-skill/references/commands.md` is generated by `scripts/gen-references.js` from built `bitget-core` (build core first). Regenerate with `pnpm gen-references`.

## Build tooling

`tsup` per package (`tsup.config.ts`), shared compiler options in `tsconfig.base.json`.

## Git workflow

- Default branch `main`. Feature branches `f/<slug>` (e.g. `f/format-code`).
- Conventional-commit style subjects (`feat:`, `style:`, `refactor:`, `docs:`).
